# Petit lexique du développeur

| Mot | Ce que ça veut dire | Pour s'en souvenir |
|---|---|---|
| **Front (frontend)** | La partie d'un site qu'on voit et qu'on touche, dans le navigateur | La salle du restaurant |
| **Back (backend)** | La partie qui tourne sur un serveur et qui calcule, stocke, décide | La cuisine |
| **API** | Les « questions » qu'on a le droit de poser au back, et la forme des réponses | Le menu du restaurant |
| **Serveur** | Un ordinateur (ou un programme) qui répond aux demandes d'autres ordinateurs | Le serveur qui prend la commande |
| **Requête** | Une demande envoyée au serveur (ex. « quel coup joues-tu ? ») | Passer commande |
| **React** | Une librairie pour construire des pages web en « briques » (composants) | Des Lego pour écrans |
| **Python** | Un langage de programmation très utilisé (IA, sciences, serveurs) | — |
| **FastAPI** | Un outil Python pour créer une API facilement | — |
| **Librairie** | Du code déjà écrit par d'autres qu'on réutilise | Ne pas réinventer la roue |
| **FEN** | Une ligne de texte qui décrit une position d'échecs | Une photo de l'échiquier, en texte |
| **UCI** | Une façon d'écrire un coup : case de départ + case d'arrivée (`e2e4`) | — |
| **Algorithme** | Une suite d'étapes précises pour résoudre un problème | Une recette de cuisine |
| **Minimax** | L'algorithme où je cherche le MAXimum pour moi, en supposant que l'adversaire cherche le MINimum pour moi | — |
| **Profondeur** | Le nombre de coups que l'ordinateur imagine à l'avance | — |
| **Élagage** | Ne pas explorer les branches dont on sait déjà qu'elles sont mauvaises | Tailler un arbre |
| **Module** | Une partie d'un logiciel, rangée à part, dont s'occupe une personne ou une équipe | Les rayons d'un magasin |
| **Branche (Git)** | Une copie de travail parallèle du projet, pour avancer sans gêner les autres | Un brouillon |
| **Fusion (merge)** | Réunir le travail de deux branches | Recopier son brouillon au propre |
| **Probabilité** | La chance qu'une chose arrive, entre 0 (jamais) et 1 (sûr), ou en % | 1 chance sur 6 avec un dé |
| **Données** | Les informations qu'on enregistre (ici : les tactiques que tu as jouées) | — |
| **Prédiction** | Ce que l'IA pense qu'il va se passer, à partir des données | La météo |
| **Apprentissage automatique (machine learning)** | Quand un programme s'améliore en observant des données au lieu de suivre des règles fixes | — |
| **Fréquence** | Combien de fois une chose arrive | — |
| **Simulation** | Faire « jouer » un modèle de la réalité par l'ordinateur, souvent avec du hasard | Un jeu vidéo de foot qui joue tout seul |
| **Méthode de Monte-Carlo** | Simuler un grand nombre de fois pour voir ce qui arrive le plus souvent | Lancer un dé 1 000 fois pour vérifier qu'il n'est pas truqué |
| **Modèle** | Une version simplifiée de la réalité, avec des règles et des chiffres | Une maquette d'avion |
| **Équilibrage** | Régler les chiffres d'un jeu pour qu'aucun choix ne soit toujours le meilleur | Un joueur trop fort et pas cher casse le jeu |
| **Loi normale** | La façon dont le hasard se répartit souvent : beaucoup de résultats proches de la moyenne, peu de résultats très loin | Les tailles des élèves d'une classe |
| **Carte de chaleur** | Une image où la couleur montre une valeur : rouge = beaucoup, jaune = un peu | La carte météo des températures |
| **Arbitre (serveur)** | Le programme qui applique les règles et décide du résultat, pour que personne ne triche | L'arbitre d'un match |
| **Test automatique** | Un petit programme qui vérifie que le code fait bien ce qu'on attend | Un contrôle technique |
| **Bug** | Une erreur dans un programme | — |
| **Git / commit** | Un outil qui garde l'historique du code ; un commit est un point de sauvegarde | Une machine à remonter le temps |
| **Compiler / build** | Transformer le code en fichiers prêts à être mis en ligne | Mettre le plat en barquette |
| **Déployer** | Mettre un programme en ligne pour que tout le monde puisse l'utiliser | Ouvrir le restaurant au public |
| **Cloud** | Des ordinateurs loués dans des centres de données | — |
| **VM (machine virtuelle)** | Un ordinateur « simulé » qu'on loue dans le cloud | Un appartement dans un immeuble |
| **Docker / conteneur** | Une boîte qui contient un programme et tout ce dont il a besoin | Un conteneur de bateau |
| **HTTPS** | Une connexion chiffrée (le cadenas dans la barre d'adresse) | — |
| **Prompt** | La consigne qu'on donne à une IA comme Claude | — |
| **Cahier des charges** | Le document qui décrit ce que le client veut | — |
